# Reflection – Laboratory Activity 1

## What I Learned
Completing this activity taught me how to navigate and work inside a Linux environment from the ground up. I learned how to create a new user account with proper permissions, gather system information using commands like `lscpu`, `free -h`, and `df -h`, and organize files and directories through the command line instead of a graphical interface. I also got hands-on experience with Git and GitHub, from creating a repository to committing and pushing changes.

## Challenges I Encountered
One of the biggest challenges was setting up Git authentication. I initially tried logging in with my GitHub password, but GitHub no longer supports password authentication for Git operations, so I had to generate a Personal Access Token instead. I also ran into an "Author identity unknown" error when trying to commit, which I fixed by configuring my Git username and email with `git config`. These issues taught me how to read error messages carefully and troubleshoot step by step instead of getting stuck.

## Why This Matters
These skills reflect real responsibilities of a cloud engineer. Being comfortable in a Linux terminal, documenting work clearly, and maintaining a version-controlled portfolio on GitHub are all foundational practices used in real cloud infrastructure and DevOps roles. This activity gave me a small taste of the onboarding process a junior cloud engineer might actually go through at a company, and it reinforced the importance of documentation and troubleshooting as core skills, not just technical commands.
